# Capability-Led Roadmap

## Why the roadmap changes now

The Decision Control Plane has moved beyond isolated feature delivery. Its next constraint is the breadth of decision problems it can **govern safely**. This roadmap therefore groups future work by durable capability rather than by page or widget, while preserving the central invariant that consequential decisions are tenant-scoped, evidence-bound, replayable events over versioned state.

> The operator lifecycle is **Observe → Investigate → Compare → Interpret → Recommend → Approve → Execute → Verify → Retain → Review**.

The current pilot has strong evidence across observe, compare, interpret, retain, and investigation intake. The present expansion strengthens the operating layer between investigation and recommendation: accountable ownership, work queues, service-level posture, comments, attachment evidence, activity history, and searchable documentation. Approval and execution continue to remain separate protected controls; they are not silently introduced by a case-management UI.

## This release’s bounded architecture

The Documentation Portal is an authenticated, application-rendered knowledge surface. It indexes curated theory, architecture, operational, process, release, ADR, and research-archive records. Search is local to the packaged documentation catalog and cross-reference navigation is explicit; it does not claim a general enterprise search service or external content synchronization.

The Investigation workspace remains tenant-scoped. A case can be assigned to an accountable investigator, given a due date and service-level target, placed in saved views, annotated by immutable comments, linked to a small pilot attachment, and represented in an immutable activity stream. Service-level posture is calculated when the case is read; this release creates **no background timer, external notification, automatic escalation, or automatic execution**.

## Deliberate deferrals

| Deferred capability                    | Why it is not introduced now                                                                                                                                                     |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Automatic SLA reminders or escalations | A reliable scheduled workflow requires a deployment and explicit escalation-recipient, retry, delivery, and operating-model choices.                                             |
| Bulk or million-case simulation        | The platform needs workload limits, data sampling governance, and comparative performance validation before making scale claims.                                                 |
| Cross-domain production adapters       | A second domain must be validated against the same kernel rather than represented as a vocabulary-only demo.                                                                     |
| AI-generated recommendations           | Evidence attribution, human authority, evaluation, and model-risk controls must precede decision assistance.                                                                     |
| Production attachment lifecycle        | This release stores attachment metadata and tenant-scoped objects; malware scanning, external DLP, automated retention deletion, and legal-hold enforcement remain out of scope. |

## Acceptance criteria for the current increment

The increment is complete only when the portal makes the architecture handbook, ADRs, core theory, current release guides, and research archive searchable and cross-linked; when investigator queues support tenant-scoped search, sorting, and saved views; when ownership and SLA posture are explicit; and when comments, attachment references, and activity records are retained under tenant checks. Tests and browser validation must demonstrate that comments and attachments cannot cross tenant boundaries and that no UI action bypasses approval, rollback, RPO, or ownership gates.
